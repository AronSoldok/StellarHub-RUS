# Охлаждение / Cooling

Вкладка **Мониторинг → Охлаждение** использует установленный драйвер NVIDIA через NVML.
Поддерживаются только каналы с чтением политики управления, температуры, числа вентиляторов,
диапазона скорости и температурного порога. Обнаружение не доказывает возможность записи.
Кнопка «Проверить управление» сначала проверяет возврат к автоматике, кратковременно задаёт
текущую скорость с учётом допустимого минимума и повторно возвращает автоматическое управление.

Кулеры CPU ноутбука, SuperIO материнских плат, AMD GPU, внешние контроллеры и помпы
пока не поддерживаются. Для HP Victus отдельный адаптер HP/EC не реализован.
При проверке на текущем ноутбуке NVML не предоставил доступных каналов. Реальное изменение
оборотов на поддерживаемом оборудовании ещё требует проверки. Дополнительные драйверы
не устанавливаются; произвольные регистры контроллера ноутбука не записываются.

## Режимы

- Автоматика драйвера, фиксированная скорость и кривая по температуре GPU.
- От 2 до 12 точек с возрастающей температурой и неубывающей скоростью.
- Ускорение без задержки, гистерезис и ограничение темпа снижения скорости.
- Начальный консервативный минимум — большее из 50% и минимума драйвера.
  Калибровка минимальных оборотов, остановка вентиляторов и управление помпами не реализованы.
- При достижении сообщённого драйвером порога замедления GPU задаётся 100% без сглаживания.
- NVML возвращает процент скорости; измеренные об/мин не подменяются расчётными.
  Нулевой процент в трёх последовательных отсчётах при ручном управлении вызывает возврат
  к автоматике. Это не заменяет тахометр и не гарантирует обнаружение механической неисправности.
- Профили сохраняются по UUID GPU и номеру вентилятора и автоматически не включаются.
  Проверка совместимости требуется в каждом новом сеансе.

Перед проверкой закройте другие программы управления вентиляторами. Глобальный mutex
исключает второй собственный контроллер StellarHub. Канал с уже включённой ручной политикой
не принимается. Обнаружение всех сторонних утилит и аппаратных конфликтов не гарантируется.

## Восстановление

Отдельный процесс регулирует скорость независимо от страницы, паузы графиков и сворачивания.
Потеря связи с главным процессом вызывает восстановление автоматики. Главный процесс следит
за контроллером и при его сбое предпринимает ограниченную по времени попытку восстановления.
Пропажа датчика, устаревшие данные после сна и ошибки записи останавливают ручную политику.
При обычном выходе восстановление выполняется до закрытия приложения.

Это программная защита, а не аппаратный watchdog: одновременное принудительное завершение
всех процессов, зависание драйвера или Windows могут помешать восстановлению. Если подтвердить
автоматику не удалось, интерфейс сообщает об ошибке. Такое сообщение не означает успешного восстановления.

## Architecture and validation

`cooling_model.py`: hardware-independent validation and regulation policy.
`cooling_nvml.py`: installed-driver adapter. `cooling.py`: controller process, heartbeat
supervision, exclusive lease, recovery and saved profiles. The interface uses the existing
`SH.engine` bridge, monitor lifecycle, design tokens and localization.

Tests use fake devices; no hardware writes occur during tests. Actual fan response and recovery
after forced process loss still require validation on compatible NVIDIA hardware before this
can be treated as a validated hardware-control release.

Argus Monitor is a functional reference; its binaries and drivers are not included:
[fan control concepts](https://www.argusmonitor.com/how_to_control_system_cpu_and_gpu_fans_by_temperature.php?language=en).
API: [NVIDIA NVML device commands](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceCommands.html).
